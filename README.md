# Touchline AI 1.0

面向校园11人制足球教练的本地优先PWA。React + TypeScript + Vite + Tailwind CSS，IndexedDB保存数据；Node/Express服务端代理AI调用。

## 本地运行

需要 Node.js 22.12+（本机已用 Node 24.18 验证）。

```powershell
cd touchline-ai
npm ci
npm run build
npm run server
```

打开 http://localhost:3001 。生产构建支持离线缓存。首次打开后待缓存完成，再离线访问相同地址。手机访问需把生产服务部署到HTTPS地址；localhost只指当前设备。

开发模式：分别运行 `npm run server` 和 `npm run dev`，打开Vite显示的地址。开发模式不启用离线服务工作线程。

## AI配置

将 `.env.example` 复制为 `.env`，填写兼容 Chat Completions 的接口根地址（例如以 `/v1` 结尾）、模型名和API密钥。服务自动追加 `/chat/completions`。模型接口需要支持 `response_format: { type: "json_object" }`。修改后重启服务。

密钥只由服务端读取，禁止使用 `VITE_` 前缀保存密钥。浏览器固定请求同源 `/api/analyze`。服务设置35秒上游超时、请求体限制、输出结构验证、单IP每分钟6次和最多3个并发请求；不记录请求资料或密钥。默认仅监听127.0.0.1。供手机使用时须自行配置HTTPS与网络访问；公开部署需配置网关访问控制以保护AI调用额度。

未配置时，AI区域明确显示“尚未配置”；不会伪造AI分析。点击分析才会发送本次球员资料与比赛事件到所配置服务。模型文字依据仍需教练审核；结构验证无法保证模型每句陈述真实。阵容操作仅在教练点击采纳后执行，且再次验证换人规则；场况变化则原建议失效。

## 使用顺序

1. 球员：首次导入原始17人。资料中的“容易受伤”不等于本场受伤；本场可用性、伤病、疲劳缺省未知。姓名、位置、惯用脚、原始特点及优先级按源文件导入，没有生成能力评分。
2. 阵容：选择三种阵型之一，安排11名首发；其他球员显示为替补/未安排。可触屏拖动站位，选人控件也可键盘操作。陌生位置提示需要确认，不默认为适配。
3. 比赛：创建对手、日期、总时长、换人总次数及是否允许再次上场。V1规则是按球员替换次数计数，不包含换人窗口/中场窗口等高级规则。一次只允许一场未结束比赛。
4. 计时：开始、暂停、继续和手动校正。计时按绝对时间恢复，不依赖后台页面每秒运行。超过总时长显示补时，教练决定何时结束。调整设备系统时间可能影响正在运行的计时，可手动校正。
5. 记录：进球、牌、伤病、疲劳、问题和备注。两黄触发罚下，不能补人。换人/变阵/站位调整须先填写原因。伤病疲劳记录的详细文本不会被自动解释成强制不可上场，由教练判断。
6. 复盘：保留创建时的球员与首发快照，展示全部事件、撤销痕迹及最终比分。事件分钟/说明可修正；对象或类型错误时撤销再记录。按记录顺序回放，不因修正分钟重新排序。涉及后续依赖的撤销会拒绝，先撤销后续关联事件。
7. 数据：支持完整JSON、球员数组、单场比赛JSON导入导出。导入先验证、预览再确认；确认时下载旧数据备份。导入后计时暂停，以免恢复的旧备份继续累计时间。浏览器下载需用户允许时请检查下载目录。

## 数据与文件

```text
players.json            原始17人资料，不参与修改
public/players.json     首次加载的原始球员副本
src/types.ts            核心类型
src/domain.ts           阵型、计时、事件回放、换人规则
src/validation.ts       JSON及AI结构和引用验证
src/storage.ts          IndexedDB读写
src/App.tsx             页面导航、球员编辑及阵容安排
src/Pitch.tsx           SVG触屏战术板
src/MatchPanel.tsx      比赛控制、事件及复盘
src/AdvicePanel.tsx     AI显示及显式采纳
src/DataPanel.tsx       备份与导入预览
src/ai.ts               AI上下文与采纳逻辑
server/index.ts         AI代理及生产静态服务
tests/                  业务单元测试
e2e/                    真实浏览器端到端测试
```

数据只在当前浏览器及当前站点地址下保存。不同端口、浏览器或手机之间不共享；用导出/导入迁移。清除浏览器数据会删除记录。保存失败时页面提示立即导出备份。首次启动需要联网加载；AI始终需要网络。应用更新采用点击确认刷新，避免自动刷新比赛页面。

## 验证

```powershell
npm run build
npm test
# 先启动 npm run server
npx playwright install chromium
npm run test:e2e
```

浏览器测试使用独立浏览器上下文，不污染教练当前浏览器数据。截图在 `test-results/`。AI真实服务未提供凭据时不做真实模型质量验收；测试使用明确的模拟响应验证流程，另测未配置错误提示。
